## 1. 면적 정직화 (가장 먼저 — 다른 항목이 이 값에 의존한다)

- [x] 1.1 면적 표기 함수를 고쳐 `min > max`인 경우 범위로 잇지 않고 두 값을 병기하며 의미 미확정을 밝힐 것. **값을 정렬해 뒤집지 말 것** — `80㎡ ~ 11,414㎡`로 만들면 "최소가 80"이라는 없는 사실이 생긴다
- [x] 1.2 정상인 경우(`min <= max`)는 기존 표기를 유지하는 것을 테스트로 고정. 실데이터에서 52%가 정상이다
- [x] 1.3 `computePricePerArea`의 반환을 `{pricePerArea, basisArea, basisField}`로 확장. 이 함수는 `workers/lib/derived.ts`가 공유하므로 **분석 프롬프트에도 기준이 들어간다** — 워커 쪽 호출부도 함께 갱신하고 테스트할 것
- [x] 1.4 화면에 기준 면적을 함께 표시(`1,296,089원/㎡ (면적 A 179㎡ 기준)`). 최소·최대가 같으면 기준 표기를 생략해도 된다
- [x] 1.5 실데이터의 실제 케이스로 테스트: 역전(id 48: 11414/80), 정상 동일값(84/84), 한쪽만 있음, 둘 다 없음

## 2. 평(坪) 병기

- [x] 2.1 ㎡ → 평 환산 순수 함수(1평 = 3.3058㎡, 소수 1자리). 원본이 정수로 절삭 저장되므로 **소수 2자리 이상 쓰지 말 것** — 없는 정밀도를 꾸며내게 된다
- [x] 2.2 목록·상세에 `84㎡ (25.4평)` 형태로 병기. 값이 없으면 기존대로 "-"
- [x] 2.3 0·null·음수 가드와 반올림 경계를 테스트

## 3. 유찰횟수-저감률 불일치 경고

- [x] 3.1 `failedBidCount`와 `minBidPriceRateRound1`의 모순을 판정하는 순수 함수. 임계는 상수로 두고 근거를 주석에 남길 것
- [x] 3.2 실데이터 케이스로 테스트: `failed=8, rate=80`(모순), `failed=16, rate=3`(정합), `failed=1, rate=100`(모순), 둘 중 하나가 null(판정 불가)
- [x] 3.3 목록·상세에 배지와 짧은 설명 표시. **어느 쪽이 맞는지 우리가 판단해 한쪽을 감추지 말 것**(design D3)

## 4. 비고 플래그

- [x] 4.1 `note` 문자열에서 실측된 유형만 판정하는 순수 함수: 일괄매각, 대항력 포기조건, 지분매각, 위반건축물, 농지취득자격증명, 보증금 20%. **없는 유형을 추측해 만들지 말 것**
- [x] 4.2 목록 소재지 칸에 배지 표시. 배지는 원문을 대체하지 않는 신호이며, 상세에서 원문을 볼 수 있어야 한다
- [x] 4.3 상세에서 비고를 **가격 카드 위**로 승격해 원문 그대로 표시
- [x] 4.4 실데이터 문자열로 테스트하고, 패턴에 안 걸리는 비고도 상세에는 원문이 나오는 것을 확인

## 5. 매각기일 D-day와 시각 포맷

- [x] 5.1 D-day 계산 순수 함수(오늘/D-N/지남). 시간대는 기존 `format.ts` 관례를 따를 것 — 맨 `YYYY-MM-DD`를 `Date`로 파싱하면 KST에서 하루 밀린다
- [x] 5.2 목록에 D-day 표시. **기본 정렬을 바꾸지 말 것**(design D5)
- [x] 5.3 상세의 매각기일 시각 `1000` → `10:00`. 389건 전부 `1000`이라 지금은 그대로 노출된다
- [x] 5.4 경계 테스트: 오늘, 어제(지남), 내일, 값 없음, 형식이 예상과 다른 경우
