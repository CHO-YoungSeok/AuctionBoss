## Purpose

수집된 경매 물건을 서버 로컬의 Claude Code로 분석하고 그 결과를 서비스에 저장·표시하는 파이프라인을 제공한다. 분석 품질(프롬프트)은 이후 계속 발전시키되, 이 capability는 "대상 선정 → 실행 → 결과 저장 → 표시"의 흐름을 계약으로 고정한다.

## ADDED Requirements

### Requirement: 분석 대상 선정
분석 워커는 분석 결과가 없는 물건을 조회해 분석 대상으로 삼아야 한다(SHALL). 한 실행 회차에서 처리할 최대 물건 수는 설정으로 제한할 수 있어야 한다(SHALL) — 분석 비용(Claude 호출 수)을 통제하기 위함이다.

#### Scenario: 미분석 물건 선정
- **WHEN** 분석 워커가 실행되면
- **THEN** 미분석 물건이 회차당 최대 건수 이내로 조회되어 순차 분석된다

#### Scenario: 분석할 물건이 없는 경우
- **WHEN** 미분석 물건이 없는 상태에서 워커가 실행되면
- **THEN** 아무 분석도 실행하지 않고 정상 종료한다

### Requirement: Claude Code 분석 실행
분석 워커는 물건 데이터를 입력으로 Claude Code를 headless 모드로 실행해 분석 결과를 얻어야 한다(SHALL). 1단계 분석 결과에는 최소한 요약 평가 텍스트와 감정가 대비 최저매각가격 비율에 대한 코멘트가 포함되어야 한다(SHALL). 개별 물건의 분석 실패는 다른 물건의 분석을 중단시켜서는 안 된다(MUST NOT).

#### Scenario: 정상 분석
- **WHEN** 미분석 물건 1건에 대해 분석이 실행되면
- **THEN** Claude Code가 물건 데이터를 입력으로 실행되고, 구조화된 분석 결과(요약 평가 포함)가 생성된다

#### Scenario: 개별 분석 실패
- **WHEN** 특정 물건의 분석 실행이 실패하면(CLI 오류, 출력 파싱 실패 등)
- **THEN** 실패가 물건 식별자와 함께 로그에 남고, 나머지 대상 물건의 분석은 계속 진행된다

### Requirement: 분석 결과 수신 API
시스템은 분석 결과를 저장하는 HTTP API(`POST /api/analyses`)를 제공해야 한다(SHALL). 분석 워커는 결과를 이 API를 통해서만 서버에 저장해야 하며(MUST), 결과에는 대상 물건 식별자, 분석 본문, 분석 시각, 사용한 분석 버전(프롬프트 버전) 식별자가 포함되어야 한다(SHALL). 존재하지 않는 물건에 대한 결과는 거부되어야 한다(MUST).

#### Scenario: 결과 저장
- **WHEN** 분석 워커가 유효한 분석 결과를 API로 전송하면
- **THEN** 결과가 해당 물건에 연결되어 저장되고 성공 응답이 반환된다

#### Scenario: 잘못된 물건 식별자
- **WHEN** 존재하지 않는 물건 식별자로 분석 결과가 전송되면
- **THEN** 404(찾을 수 없음) 오류가 반환되고 아무것도 저장되지 않는다

### Requirement: 분석 결과 표시
물건 상세 페이지는 해당 물건의 최신 분석 결과를 표시해야 한다(SHALL). 분석 결과가 아직 없으면 "분석 대기 중"임을 안내해야 한다(SHALL).

#### Scenario: 분석 완료 물건 상세
- **WHEN** 분석 결과가 저장된 물건의 상세 페이지를 열면
- **THEN** 분석 요약과 분석 시각이 물건 정보와 함께 표시된다

#### Scenario: 분석 전 물건 상세
- **WHEN** 아직 분석되지 않은 물건의 상세 페이지를 열면
- **THEN** 물건 정보는 정상 표시되고 분석 영역에는 대기 중 안내가 표시된다
