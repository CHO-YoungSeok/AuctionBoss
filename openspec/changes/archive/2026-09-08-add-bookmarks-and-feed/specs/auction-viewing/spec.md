## MODIFIED Requirements

### Requirement: 물건 목록 열람
시스템은 저장된 물건의 목록 페이지를 제공해야 한다(SHALL). 목록에는 최소한 소재지, 용도, 감정가, 최저매각가격, 매각기일, 유찰횟수, 진행상태가 표시되어야 하며(SHALL), 매각기일 오름차순을 기본 정렬로 하고 페이지네이션을 지원해야 한다(SHALL).

목록 페이지는 용도(다중 선택), 최저매각가격 범위, 유찰횟수 최소값, 소재지 키워드로 결과를 좁히는 필터를 제공해야 한다(SHALL). 정렬 기준(매각기일, 최저매각가격, 감정가 대비 최저가 비율, 유찰횟수)과 방향(오름/내림차순)을 사용자가 선택할 수 있어야 한다(SHALL). 적용된 필터·정렬·페이지 상태는 URL에 반영되어야 하며(MUST), 그 URL을 다시 열면 같은 결과가 재현되어야 한다(SHALL).

목록의 각 물건은 관심 목록에 담겼는지 알 수 있어야 하며(SHALL), 목록에서 바로 담고 뺄 수 있어야 한다(SHALL). 관심 여부 표시가 기존 필터·정렬·전체 건수 계산에 영향을 주어서는 안 된다(MUST NOT).

#### Scenario: 목록 조회
- **WHEN** 사용자가 물건 목록 페이지에 접속하면
- **THEN** 저장된 물건들이 매각기일이 가까운 순으로 페이지 단위로 표시된다

#### Scenario: 물건이 없는 경우
- **WHEN** 아직 수집된 물건이 없는 상태에서 목록 페이지에 접속하면
- **THEN** 오류 대신 "물건이 없다"는 안내가 표시된다

#### Scenario: 용도로 필터
- **WHEN** 사용자가 용도 필터에서 하나 이상의 용도를 선택하면
- **THEN** 선택한 용도에 해당하는 물건만 표시되고, 전체 건수도 필터 적용 후 기준으로 표시된다

#### Scenario: 가격 범위로 필터
- **WHEN** 사용자가 최저매각가격의 최소값·최대값을 지정하면
- **THEN** 그 범위 안의 물건만 표시된다. 한쪽만 지정하면 그 방향으로만 제한된다

#### Scenario: 소재지 키워드 검색
- **WHEN** 사용자가 소재지 키워드를 입력하면
- **THEN** 소재지에 그 키워드를 포함하는 물건만 표시된다

#### Scenario: 정렬 변경
- **WHEN** 사용자가 정렬 기준과 방향을 선택하면
- **THEN** 목록이 그 기준으로 정렬되고, 값이 없는(null) 물건은 정렬 방향과 무관하게 뒤에 배치된다

#### Scenario: 필터 결과가 없는 경우
- **WHEN** 적용된 필터에 맞는 물건이 하나도 없으면
- **THEN** 오류 대신 조건에 맞는 물건이 없다는 안내와 필터를 초기화할 수단이 표시된다

#### Scenario: 필터 상태가 URL에 보존됨
- **WHEN** 사용자가 필터·정렬을 적용한 뒤 그 URL을 새로 열거나 공유하면
- **THEN** 같은 필터·정렬·페이지가 적용된 동일한 결과가 표시된다

#### Scenario: 선택 가능한 용도 목록
- **WHEN** 목록 페이지가 용도 필터를 표시하면
- **THEN** 선택지는 현재 저장된 물건들에 실제로 존재하는 용도에서 도출된다(고정 목록이 아니다)
#### Scenario: 목록에서 관심 표시
- **WHEN** 관심 목록에 담긴 물건과 담기지 않은 물건이 함께 표시되면
- **THEN** 담긴 물건을 구별할 수 있고, 각 행에서 담고 빼는 조작을 할 수 있다

#### Scenario: 관심 표시가 필터에 영향 없음
- **WHEN** 필터와 정렬이 적용된 목록에서 관심 여부가 표시되면
- **THEN** 필터 결과와 전체 건수가 관심 여부와 무관하게 이전과 동일하다

### Requirement: 물건 상세 열람
시스템은 개별 물건의 상세 페이지를 제공해야 한다(SHALL). 상세에는 목록 표시 항목에 더해 사건번호, 물건번호, 담당 법원, 수집 시각이 표시되어야 한다(SHALL).

수집된 확장 정보도 표시되어야 한다(SHALL): 면적과 건물 구조, 차수별 최저매각가격, 용도 분류, 구조화된 소재지, 매각기일 시각·장소, 사건 비고, 담당계 연락처. 값이 없는 항목은 없음을 알 수 있게 표시해야 하며(SHALL), 값이 없다는 이유로 화면이 오류가 나서는 안 된다(MUST NOT).

소스가 여러 줄로 주는 값(건물 구조·면적 서술 등)은 줄바꿈이 보존되어 읽을 수 있게 표시되어야 한다(SHALL).

상세 페이지에서도 관심 목록에 담고 뺄 수 있어야 하며(SHALL), 현재 담긴 상태가 표시되어야 한다(SHALL).

#### Scenario: 상세 조회
- **WHEN** 사용자가 목록에서 물건을 선택하면
- **THEN** 해당 물건의 상세 정보 페이지가 표시된다

#### Scenario: 존재하지 않는 물건
- **WHEN** 존재하지 않는 물건 ID로 상세 페이지에 접근하면
- **THEN** 404(찾을 수 없음) 응답이 반환된다

#### Scenario: 확장 정보 표시
- **WHEN** 면적·차수별 최저가·용도 분류가 수집된 물건의 상세 페이지를 열면
- **THEN** 그 값들이 사람이 읽을 수 있는 형태로 표시된다

#### Scenario: 확장 정보가 없는 물건
- **WHEN** 확장 필드가 비어 있는 물건(이 기능 이전에 수집된 물건 포함)의 상세 페이지를 열면
- **THEN** 오류 없이 기존 정보가 정상 표시되고 없는 항목은 없음으로 표시된다

#### Scenario: 여러 줄 값 표시
- **WHEN** 건물 구조·면적처럼 줄바꿈이 포함된 값을 표시하면
- **THEN** 줄바꿈이 보존되어 한 줄로 뭉개지지 않는다
#### Scenario: 상세에서 관심 토글
- **WHEN** 상세 페이지에서 관심 담기를 하면
- **THEN** 담긴 상태로 바뀌고 같은 상세 페이지가 유지된다
