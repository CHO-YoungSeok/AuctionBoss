# Proposal: add-bookmarks-and-feed

## Why

지금 이 서비스를 쓰려면 매번 목록을 처음부터 훑어야 한다. 관심 있는 물건을 표시해둘 방법이 없어서, 어제 봐둔 물건을 다시 찾으려면 필터 조건을 기억해 재입력해야 한다.

더 중요한 건 **변동을 놓친다**는 점이다. 2회차에서 변경 이력을 기록하게 만들었고 3회차에서 수집이 실제로 도는지 보게 만들었지만, 정작 **"내가 관심 있는 물건에 무슨 일이 생겼는지"를 알려주는 경로가 없다.** 유찰로 최저가가 떨어지는 순간이 이 서비스가 포착하는 가장 값진 정보인데, 사용자가 그걸 알려면 상세 페이지를 직접 열어봐야 한다. 10분마다 수집하는 의미가 절반은 사라진다.

## What Changes

- 물건을 관심 목록에 담고 뺄 수 있게 한다. 목록·상세 양쪽에서 가능해야 한다.
- 관심 물건만 모아 보는 화면을 제공한다.
- **변동 피드**: 관심 물건에 생긴 실제 변경(최저가 하락, 유찰횟수 증가, 매각기일 변경, 진행상태 전이)을 최신순으로 모아 보여준다. 무엇이 언제 어떻게 바뀌었는지와 해당 물건으로 가는 링크를 포함한다.
- 피드에 **읽음 표시**를 둔다. 마지막으로 확인한 시점 이후의 변동을 구별할 수 있어야 하며, 그렇지 않으면 매번 전체를 다시 훑게 되어 피드가 무의미해진다.
- 관심 물건 수와 미확인 변동 수를 화면에서 알 수 있게 한다.
- 관심 물건·변동 피드 조회 API를 제공한다.

**BREAKING 아님**: 기존 목록·상세·API의 동작은 그대로다. 관심 표시가 없는 물건의 열람 경험은 변하지 않는다.

비목표(후속): 이메일·푸시 알림(외부 발송 인프라와 인증이 선행돼야 한다), 관심 조건 저장(특정 필터에 맞는 새 물건 자동 담기), 여러 사용자 지원, 메모·태그.

## Capabilities

### New Capabilities

- `bookmarks`: 관심 물건 등록·해제·조회, 관심 물건의 변동 피드, 읽음 처리.

### Modified Capabilities

- `auction-viewing`: "물건 목록 열람"과 "물건 상세 열람" 요구사항에 관심 표시·토글이 추가된다.

## Impact

- 새 테이블 2개(관심 물건, 읽음 표시) + 마이그레이션. 기존 테이블은 건드리지 않는다.
- 변동 피드는 기존 `item_changes`를 관심 물건으로 걸러 읽는다 — **새로운 이력 저장은 없다.** 2회차가 만든 `kind` 구별을 그대로 써서 기준점 행은 변동으로 세지 않는다.
- 목록·상세 페이지에 토글 UI, 새 페이지 2개(관심 목록, 변동 피드), 새 API.
- 관심 표시는 쓰기 동작이라 API가 필요하다. **인증이 없다** — 3회차에서 회차 기록 쓰기 API에 대해 이미 같은 판단을 했고 README에 경고를 남겼다. 같은 전제(로컬/내부 전용)를 따르되, 이 change로 인증 없는 쓰기 엔드포인트가 늘어난다는 점을 README에 함께 기록한다.
- **단일 사용자 전제**: 사용자 개념이 없으므로 관심 목록은 전역이다. 이 전제를 스펙과 코드에 명시해, 나중에 다중 사용자가 필요해질 때 무엇을 바꿔야 하는지 분명히 남긴다.
