# Proposal: improve-item-discovery-ux

## Why

지금 화면은 **수집한 필드를 나열할 뿐, 사용자가 판단하도록 돕지 않는다.** 구체적으로:

- **분석이 없으면 아무 판단 근거가 없다.** 분석은 회차당 5건씩 처리되므로 수백 건 중 대부분은 오랫동안 "분석 대기 중"이다. 그런데 분석 없이도 감정가 대비 최저가 비율, 면적당 가격, 유찰 횟수만으로 1차 선별은 충분히 가능하다. 그 값들은 이미 수집·계산되어 있는데 목록에 없다.
- **원본을 확인할 경로가 없다.** 사용자가 진지하게 검토하려면 결국 법원경매정보에서 사건을 봐야 하는데, 화면에 사건번호는 있어도 거기서 무엇을 해야 하는지 알려주지 않는다.
- **목록이 판단을 돕는 순서로 정렬되지 않는다.** 기본 정렬이 매각기일순인데, "좋은 물건 찾기"의 첫 질문은 보통 "얼마나 싸졌나"다.

이 change의 목표는 **분석을 기다리지 않고도 물건을 파악하고 걸러낼 수 있게** 만드는 것이다.

## What Changes

- **목록에 판단 지표를 노출한다**: 감정가 대비 최저가 비율(%)과 면적당 가격. 둘 다 이미 계산 로직이 있다(`computePricePerArea`, `bidRatio` 정렬). 비율은 저감 단계를 한눈에 보여주므로 시각적으로도 구별되게 한다.
- **법원경매정보로 연결**: 물건 상세와 목록에서 원본 사이트로 가는 링크를 제공한다. 조사 결과 **특정 물건을 가리키는 GET URL은 존재하지 않으므로**(아래 Impact 참조), 홈으로 보내되 그 자리에서 검색에 필요한 값(법원명·사건번호)을 **복사할 수 있게** 하고 무엇을 해야 하는지 한 줄로 안내한다. 깨진 딥링크를 주지 않는다.
- **분석 상태를 정직하게 표시한다**: "분석 대기 중"이 언제까지인지 알 수 없으면 사용자는 기다릴지 판단할 수 없다. 대기 중인 물건이 몇 번째인지 또는 분석이 어떤 상태인지(대기/최신/재분석 예정) 알 수 있게 한다.
- **상세 화면을 판단 순서로 재구성한다**: 지금은 수집 필드 순서대로 나열되어 있다. 가격·저감 → 물건 개요(면적·용도·소재지) → AI 분석 → 변경 이력 → 원본 확인 → 부가 정보 순으로, 사람이 물건을 볼 때의 순서에 맞춘다.
- **목록에서 핵심 정보를 잃지 않게 한다**: 소재지가 길어 잘리면 어느 동네인지 알 수 없다. 구조화된 소재지(4회차 산출물)를 활용해 지역을 요약 표시한다.

**BREAKING 아님**: 기존 필터·정렬·API 계약·URL 파라미터는 그대로 유지한다. 표시와 배치만 바뀐다.

비목표(후속 9회차): 사진, 지역별 필터, 평 단위 표시, 가격 필터 개선 — 사용자가 9회차 이슈로 지정했다. 이번에는 그 기반이 되는 표시 구조만 정리한다.

## Capabilities

### New Capabilities

(없음)

### Modified Capabilities

- `auction-viewing`: "물건 목록 열람"에 판단 지표 표시와 지역 요약이 추가된다. "물건 상세 열람"에 원본 사이트 연결과 정보 배치 요구사항이 추가된다.
- `auction-analysis`: "분석 결과 표시" 요구사항에 분석 상태(대기/최신/재분석 예정)를 알 수 있어야 한다는 내용이 추가된다.

## Impact

- `src/app/page.tsx`(목록 열), `src/app/items/[id]/page.tsx`(상세 재구성), `src/app/_lib/**`(표시 헬퍼).
- **딥링크 불가 (조사로 확인)**: 법원경매정보는 WebSquare5 SPA이고, 물건 식별자는 URL이 아니라 화면 간 인메모리 파라미터로만 전달된다. 상세 화면 XML 171KB 전체에 `location.search`/`location.hash`/`URLSearchParams`가 **0건**이다. `index.on?w2xPath=...`로 화면 선택은 가능하지만 물건 지정 파라미터가 없어, 그 링크는 데이터 없는 빈 화면이나 오류로 이어질 위험이 홈보다 크다. 따라서 **홈 링크 + 복사 가능한 검색값**이 최선이다.
- 데이터 계층 변경 없음 — 필요한 값(감정가, 최저가, 면적, 구조화 소재지, 분석·이력)은 이미 전부 저장되어 있다. 이 change는 **이미 가진 것을 보여주는 방식**에 관한 것이다.
- 클라이언트 JS를 쓰지 않는 기존 규칙을 유지한다. 복사 기능은 JS 없이 선택하기 쉬운 형태(예: `<input readonly>`)로 제공한다.
