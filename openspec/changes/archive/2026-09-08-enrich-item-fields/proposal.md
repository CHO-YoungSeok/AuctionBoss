# Proposal: enrich-item-fields

## Why

AI 분석이 지금 보는 것은 **필드 10개 + 시각 3개**뿐이다. 프롬프트 자신이 "등기부·권리관계·임차인·실거래가·시세·사진은 주어지지 않았다"고 명시하고 있다. 분석 품질의 병목이 데이터 부족인 것은 확실하다.

그런데 **목록 응답에는 이미 훨씬 많은 데이터가 오고 있고, 어댑터의 zod 스키마가 그걸 버리고 있다.** 조사(`src/lib/sources/courtauction/NOTES.md` §3.1, §8)에서 실제 응답과 fixture로 확인된 필드가 30개 가까이 되며, 면적·차수별 최저가처럼 경매 판단에 직접 쓰이는 것들이 포함된다.

상세 엔드포인트를 붙이는 대안은 배제한다. NOTES §10.5의 실측 기반 계산으로 물건당 1요청 = **회차당 402요청**이고, 실제 차단을 유발한 임계(5분에 15회 미만)의 약 27배다. 반면 이 change는 **추가 HTTP 요청이 0건**이다 — 이미 받고 있는 응답을 버리지 않기만 하면 된다.

## What Changes

- 어댑터의 응답 스키마와 정규화 변환을 확장해, 목록 응답에서 이미 오는 다음 필드를 보존한다:
  - **면적**: 최소/최대 면적, 건물 구조·면적 텍스트
  - **차수별 최저매각가격**: 1~4차 및 최저가율 (현재는 1차만 사용)
  - **용도 분류 코드**: 대/중/소분류 (현재는 사람이 읽는 텍스트만)
  - **소재지 구조화 값**: 시/도, 시/군/구, 동, 대표지번, 건물명
  - **좌표**: x/y 좌표와 좌표 수준
  - **매각 관련**: 매각기일 시각, 매각장소, 매각결정기일, 매각기일 회차
  - **사건 관련**: 비고(예: "일괄매각"), 중복·병합 사건번호, 담당계·전화
  - **소스 원시 상태 코드**: 진행상태 코드 등 — 코드표를 모르므로 **원문 그대로만** 보존한다
- 새 필드를 물건 상세 화면에 표시한다.
- 새 필드를 AI 분석 입력에 포함하고 프롬프트를 v2로 올린다. 면적당 가격, 차수별 저감 추이처럼 새로 가능해진 판단을 프롬프트가 활용하게 한다.
- 기존 DB에 컬럼을 추가하는 마이그레이션을 제공한다. 이미 저장된 물건은 다음 수집 때 값이 채워진다.

**BREAKING 아님**: 기존 필드·API 응답 형태·`AuctionSource` 계약은 유지한다. 새 필드는 모두 nullable이며, 값이 없어도 기존 동작이 그대로여야 한다.

비목표(후속): 상세 엔드포인트 연동(별도 스파이크 선행 필요, NOTES §10.6), 사진 수집, 감정평가서·현황조사서, 좌표 기반 지도 표시, 면적 기준 필터·정렬.

## Capabilities

### New Capabilities

(없음)

### Modified Capabilities

- `auction-collection`: "소스 어댑터 계약" 요구사항의 정규화 모델이 확장된다. 소스가 값을 주지 않는 필드의 처리와, 의미를 모르는 코드값의 보존 규칙이 추가된다.
- `auction-analysis`: "Claude Code 분석 실행" 요구사항에 확장된 입력과 프롬프트 버전 상승이 반영된다.
- `auction-viewing`: "물건 상세 열람" 요구사항에 새 필드 표시가 추가된다.

## Impact

- `src/lib/sources/courtauction/schema.ts`(zod 스키마 확장)와 `adapter.ts`(정규화 변환). 소스 고유 필드명이 어댑터 밖으로 새지 않아야 한다는 기존 원칙은 그대로 지킨다.
- `src/lib/domain/types.ts`의 `AuctionItem`/`AuctionItemInput` 확장, `items` 테이블 컬럼 추가 + 마이그레이션.
- 물건 상세 페이지, 분석 프롬프트 템플릿(v1 → v2).
- **비용 영향**: 프롬프트 버전이 올라가면 이미 분석된 모든 물건이 재분석 대상이 된다(아카이브된 `add-price-change-history`의 설계). 이는 의도된 비용 결정이며, 재분석 한도와 쿨다운이 이미 그 속도를 제한한다.
- **변경 이력 영향 주의**: 새 필드를 감시 대상(`WATCHED_FIELDS`)에 넣으면 기존 물건 전체가 "변경됨"으로 기록되어 대량 재분석이 유발된다. 이번 change에서는 감시 대상을 늘리지 않는다.
