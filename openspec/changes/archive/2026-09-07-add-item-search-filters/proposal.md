# Proposal: add-item-search-filters

## Why

서울중앙지방법원 한 곳만 2개월 범위로 수집해도 444행(물건 389건)이 나온다. 현재 목록은 매각기일 오름차순 전체 나열뿐이라, 사용자가 관심 있는 물건(예: 아파트, 5억 이하, 유찰 3회 이상)을 찾으려면 페이지를 계속 넘겨야 한다. 열람이 이 서비스의 핵심 가치인데 지금 상태로는 실질적으로 열람이 불가능하다.

## What Changes

- 목록 페이지와 목록 API에 필터를 추가한다: 용도(다중 선택), 최저매각가격 범위(최소/최대), 유찰횟수 최소값, 소재지 키워드 검색.
- 정렬 옵션을 추가한다: 매각기일(기본), 최저매각가격, 감정가 대비 최저가 비율, 유찰횟수 — 각각 오름/내림차순.
- 필터·정렬 상태를 URL 쿼리 파라미터로 유지해 새로고침·공유·뒤로가기에서 보존한다.
- 필터에 걸린 결과가 0건일 때 "조건에 맞는 물건이 없다"는 안내와 필터 초기화 수단을 제공한다.
- 용도 선택 목록은 하드코딩하지 않고 현재 저장된 데이터에서 도출한다(수집 범위가 늘면 자동으로 늘어나야 한다).
- **BREAKING 아님**: 기존 `GET /api/items`의 파라미터·응답 형태는 유지하고 새 파라미터만 추가한다. analyzer 워커가 쓰는 `?analyzed=false&pageSize=N` 계약은 그대로 동작해야 한다.

비목표(후속): 지도 기반 검색, 저장된 검색 조건, 전문 검색 엔진 도입, 페이지네이션 방식 변경(커서 등).

## Capabilities

### New Capabilities

(없음)

### Modified Capabilities

- `auction-viewing`: "물건 목록 열람"과 "물건 조회 API" 요구사항에 필터·정렬·키워드 검색 동작과 결과 없음 처리가 추가된다.

## Impact

- `src/lib/db/repository.ts`의 `listItems` 시그니처와 쿼리 확장(필터 조건, 동적 정렬). 새 조회 함수로 용도 목록 도출.
- `src/app/api/items/route.ts`의 파라미터 검증 확장.
- `src/app/page.tsx`에 필터 UI 추가.
- 인덱스 추가 검토(`usage_type`, `min_bid_price`) — 현재 데이터 규모에서는 성능 문제가 없지만 정렬·필터 조합이 늘어나므로 확인한다.
- analyzer 워커는 변경 없음(기존 파라미터 계약 유지가 전제).
