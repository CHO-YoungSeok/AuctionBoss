# Proposal: ux-overhaul-phase2

## Why

Phase 1이 **틀린 표시**를 고쳤다면, Phase 2는 **찾을 수 없는 문제**를 고친다. 실데이터 389건에서 측정된 사실:

- **용도 필터가 후보의 83%를 조용히 숨긴다.** `usage_type`이 복합 문자열이라 `"상가,오피스텔,근린시설"`(115건)과 `"오피스텔"`(24건)이 별개 값이다. 필터가 정확 일치라 "오피스텔"을 체크하면 115건이 통째로 빠진다. 사용자는 24건만 보고 "오피스텔이 별로 없네"라고 잘못된 결론을 내린다.
- **지역을 좁힐 수 없다.** 관악구가 183건(47%)이라 목록이 사실상 관악구 목록이다. 강남 45건만 보려면 주소 부분일치(`q=강남`)를 쓸 수밖에 없는데 그건 "강남대로"가 있는 서초구 물건도 잡는다. `sido`/`sigungu`가 이미 저장되어 있는데 필터가 없다.
- **가격 입력이 원 단위 11자리다.** 실데이터가 76만원~261억이라 261억을 치려면 `26100000000`을 입력해야 한다. 0 하나 틀리면 조용히 10배 다른 결과가 나오고, 화면 어디에도 "지금 얼마로 걸려 있는지"가 사람이 읽는 단위로 안 보인다.
- **면적당 가격 정렬이 없다.** 저평가 물건을 찾는 가장 직접적인 축인데 목록에 열만 있고 정렬이 안 돼 20행씩 눈으로 비교해야 한다.
- **필터 상태가 안 보인다.** 폼이 항상 펼쳐져 화면 상단을 먹는데, 정작 무엇이 걸려 있는지는 입력칸을 하나씩 훑어야 안다. 조건 하나만 빼려면 그 칸을 지우고 다시 제출해야 한다.

## What Changes

- **용도 필터를 토큰 매칭으로**: 저장된 복합 문자열을 쉼표로 쪼개 선택지를 만들고, 매칭을 정확 일치에서 토큰 포함으로 바꾼다. **이것은 기존 API 계약을 바꾸는 유일한 항목이다** — 같은 `usage=오피스텔` 요청이 24건에서 139건을 반환하게 된다.
- **지역 필터**: `sido`/`sigungu` 다중 선택. 선택지는 저장 데이터에서 도출한다(법원을 늘리면 지역이 늘어나므로 고정 목록 금지). `dong`은 이번에 넣지 않는다 — 관악구만 동이 수십 개라 체크박스가 감당하지 못한다.
- **가격 필터 개선**: 입력 단위를 억/만원으로 바꾸고 프리셋(`1억 이하`/`1~3억`/`3~5억`/`5~10억`/`10억+`)을 제공한다. **API 파라미터는 원 정수 그대로 유지**하고 폼과 표시만 바꾼다 — 워커 계약과 기존 400 테스트를 지키기 위함이다.
- **면적당 가격 정렬 추가**: Phase 1이 면적 표기를 정직화한 뒤에만 의미가 있다.
- **매각기일 범위 필터**: `from`/`to`와 "지난 기일 제외". **전부 opt-in이며 기본 동작을 바꾸지 않는다** — 기본값으로 만들면 121건(31%)이 조용히 사라진다.
- **관심 물건 필터**: 목록에서 `관심만 보기` / `관심 제외`.
- **필터 상태 가시화**: 적용 중인 조건을 칩으로 표시하고 개별 해제 링크 제공, 폼은 `<details>`로 접기(필터가 걸려 있으면 펼침), 페이지 크기 선택 추가.

비목표(이후): 사진(별도 사이클), 관련 물건 링크, 관심 화면 통일, 신규 물건 배지, 지도.

## Capabilities

### New Capabilities

(없음)

### Modified Capabilities

- `auction-viewing`: "물건 목록 열람"과 "물건 조회 API"에 지역·기일·관심 필터, 용도 토큰 매칭, 면적당 가격 정렬, 필터 상태 표시가 추가된다.

## Impact

- **이 change의 위험이 지금까지 중 가장 크다.** 목록 쿼리의 `WHERE`/`ORDER BY`/`total`을 건드리며, 필터 파라미터 하나를 추가하려면 여섯 곳을 동시에 고쳐야 한다: `ITEM_QUERY_PARAMS`, zod 스키마, `ItemQuery`, **`hasActiveFilters`**, `buildFilter`, `itemQuerySearchParams`.
  - `hasActiveFilters`가 빠지면 필터로 0건일 때 "아직 수집된 물건이 없습니다"라는 **거짓 안내**가 뜨고 초기화 링크도 안 나와 사용자가 빠져나갈 수 없다. 실제로 `analyzed`가 이렇게 빠져 사고가 났다.
  - `itemQuerySearchParams`가 빠지면 **페이지 "다음"을 누르는 순간 필터가 사라진다.**
- 용도 토큰 매칭은 API 계약 변경이므로 기존 필터 테스트를 갱신하고 README의 "저장된 값과 정확히 일치" 서술도 함께 고쳐야 한다.
- 분석 워커는 `usage`를 쓰지 않으므로 워커 계약은 안전하다.
- 추가 HTTP 요청 없음. 클라이언트 JS 없음.
