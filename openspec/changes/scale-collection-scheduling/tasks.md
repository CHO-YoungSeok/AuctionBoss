- [x] 1.1 `config/collector.json`에 `scope.maxCourtsPerRun`(기본 1)과 안전장치 `scope.maxRequestsPerRun`을 추가하고 zod 스키마·로더에 반영. 잘못된 값은 조용히 기본값으로 넘어가지 않고 실패할 것
- [x] 1.2 `collector_state(key PK, value, updated_at)` 키-값 테이블을 스키마에 추가하고, 기존 DB 파일 마이그레이션 경로를 이 프로젝트의 기존 방식대로 테스트
- [x] 1.3 `getCollectorState(key)` / `setCollectorState(key, value)`를 구현하고 테스트. 로테이션 키를 상수로 정의하고 용도를 주석으로 남길 것

## 2. 로테이션

- [x] 2.1 로테이션 선택 로직을 **순수 함수**로 구현: (법원 목록, 저장된 시작 법원 코드, 회차당 상한) → (이번 회차 대상 법원 목록, 다음 시작 법원 코드). 원형 순환이며 목록 순서를 따를 것
- [x] 2.2 저장값을 **법원 코드**로 다루고, 그 코드가 목록에 없으면 처음부터 시작하도록 구현 — 설정에서 법원이 삭제·재정렬돼도 엉뚱한 법원을 가리키지 않아야 한다. 삭제·추가·재정렬 각각을 테스트
- [x] 2.3 순환 공평성 테스트: 법원 3곳 × 상한 1곳으로 3회차를 돌리면 각 법원이 정확히 한 번씩 수집되고, 6회차면 두 번씩인 것을 확인
- [x] 2.4 **회귀(가장 중요)**: 법원 1곳 + 상한 1곳이면 여러 회차에 걸쳐 매번 그 법원을 수집하고, 수집 결과·요청 수·회차 기록이 이 기능 도입 전과 동일한 것을 테스트로 고정

## 3. 워커 연동

- [x] 3.1 `workers/collector.ts`가 전체 법원 대신 로테이션이 고른 법원만 수집하도록 변경. 회차 종료 시 다음 시작 위치를 저장할 것
- [x] 3.2 회차 기록의 `detail.targetCourts`에 이번 회차가 **실제로** 처리한 법원을 남기는 것을 확인(필드는 3회차에서 이미 만들어져 있다)
- [x] 3.3 **차단 시 로테이션 위치를 전진시키지 않는 것**을 테스트 — 전진시키면 차단당한 법원만 계속 늦어진다. 백오프 후 같은 법원부터 재개하는 것도 확인
- [x] 3.4 차단이 감지되면 같은 회차에서 다음 법원으로 요청을 보내지 않는 것을 테스트(차단은 IP 단위라 법원을 바꿔도 막히고 요청만 늘어난다)
- [x] 3.5 `maxRequestsPerRun` 안전장치: 초과하면 **다음 법원을 시작하지 않되 진행 중인 법원은 끊지 않는** 동작을 구현하고 테스트. 법원을 중간에 끊으면 부분 수집된 결과가 "물건이 줄었다"로 오해된다

## 4. 상태 표시

- [x] 4.1 한 바퀴 소요 시간(`ceil(법원 수 / maxCourtsPerRun) × intervalMs`)을 계산하는 순수 함수를 만들고 테스트(법원 1곳, 나누어떨어지지 않는 경우 포함)
- [x] 4.2 `/status`에 한 바퀴 소요 시간과 현재 로테이션 위치를 표시. 법원을 추가할 때의 신선도 대가가 눈에 보이게 할 것
- [x] 4.3 회차 목록에서 각 회차가 어떤 법원을 돌았는지 보이는 것을 확인
