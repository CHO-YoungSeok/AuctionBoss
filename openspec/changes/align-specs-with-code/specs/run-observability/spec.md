## MODIFIED Requirements

### Requirement: 실행 회차 기록
시스템은 수집·분석 워커의 실행 회차마다 기록을 저장해야 한다(SHALL). 기록에는 워커 종류, 시작 시각, 종료 시각, 결과 구분, 처리 결과 수치가 포함되어야 한다(SHALL).

결과 구분은 최소한 **성공 / 실패 / 차단 / 건너뜀**을 구별해야 한다(MUST). 차단을 일반 실패와 같게 기록해서는 안 된다(MUST NOT) — 원인과 대응이 다르고, 차단은 이 시스템의 핵심 리스크이기 때문이다.

실패·차단 기록에는 오류 종류와 사람이 읽을 수 있는 메시지가 포함되어야 한다(SHALL).

수집 회차 기록에는 그 회차가 실제로 처리한 법원이 포함되어야 한다(SHALL). 설정된 전체 법원을 한 바퀴 도는 데 걸리는 예상 시간을 조회할 수 있어야 하며(SHALL), 상태 화면에 표시되어야 한다(SHALL) — 법원을 추가할 때 신선도가 얼마나 나빠지는지 미리 알 수 있어야 한다.

수집 워커는 이전 회차가 아직 실행 중이거나 차단 백오프 중이어서 건너뛴 주기를 건너뜀 사유와 함께 회차 기록으로 남겨야 한다(SHALL). 분석 워커가 이전 회차와 겹쳐 건너뛴 주기는 회차 기록이 아니라 로그로 남긴다(SHALL).

회차를 기록하는 워커 종류는 수집·분석·사진 워커이며, 사진 워커도 수집·분석 워커와 같은 기록 형식(워커 종류, 시작·종료 시각, 결과 구분, 실패·차단 시 오류 종류와 메시지)으로 실행 회차를 기록해야 한다(SHALL). 외부 소스에 요청하는 워커가 둘 이상이면 차단 백오프는 그 워커들 사이에 공유되어야 한다(MUST) — 차단은 IP 단위이므로 한 워커가 차단을 유발한 뒤 다른 워커가 계속 요청하면 차단이 연장된다.

#### Scenario: 성공 회차 기록
- **WHEN** 수집 회차가 정상 완료되면
- **THEN** 시작·종료 시각과 성공 구분, 수집된 물건 수와 신규·갱신·변경 건수가 기록된다

#### Scenario: 차단 회차 기록
- **WHEN** 수집 중 로봇탐지 차단이 감지되면
- **THEN** 그 회차가 일반 실패가 아닌 차단으로 구별되어 기록되고, 오류 종류를 알 수 있다

#### Scenario: 일반 실패 회차 기록
- **WHEN** 응답 형식 변경이나 네트워크 오류로 회차가 중단되면
- **THEN** 그 회차가 실패로 기록되고 오류 종류와 메시지가 남는다

#### Scenario: 건너뜀 기록
- **WHEN** 수집 워커가 이전 회차가 아직 실행 중이거나 차단 백오프 중이어서 이번 주기를 건너뛰면
- **THEN** 건너뜀 사유를 알 수 있는 기록이 남는다

#### Scenario: 진행 중 회차
- **WHEN** 회차가 시작되었으나 아직 끝나지 않았으면
- **THEN** 시작 시각이 기록된 미완료 상태로 조회되고, 종료 후 같은 회차 기록이 결과와 함께 갱신된다
#### Scenario: 회차별 대상 법원 기록
- **WHEN** 로테이션으로 일부 법원만 수집한 회차가 기록되면
- **THEN** 그 회차가 어떤 법원을 처리했는지 기록에서 확인할 수 있다

#### Scenario: 한 바퀴 소요 시간 표시
- **WHEN** 여러 법원이 설정된 상태에서 상태 화면을 열면
- **THEN** 전체 법원을 한 번씩 수집하는 데 걸리는 예상 시간이 표시된다
#### Scenario: 워커 간 차단 백오프 공유
- **WHEN** 한 워커가 차단을 감지하면
- **THEN** 외부 소스에 요청하는 다른 워커도 백오프가 끝날 때까지 요청하지 않는다

### Requirement: 실행 상태 판정
시스템은 최근 기록으로부터 워커의 현재 상태를 판정해 제공해야 한다(SHALL). 상태는 최소한 **정상 / 차단 / 실패 / 미실행**을 구별해야 한다(MUST). 기대 주기의 몇 배 이상 성공 기록이 없으면 정상으로 판정해서는 안 된다(MUST NOT) — 워커가 죽은 상태를 정상으로 보고하면 이 기능의 목적이 사라진다.

미실행에 해당하지 않으면, 마지막으로 완료된 회차의 결과로 차단·실패를 판정해야 한다(SHALL): 그 결과가 차단이면 차단, 실패이면 실패다. 완료된 회차는 성공·실패·차단으로 끝난 회차이며, 진행 중이거나 건너뛴 회차는 이 판정에 쓰지 않는다(SHALL).

#### Scenario: 정상 상태
- **WHEN** 최근에 성공 회차가 있으면
- **THEN** 상태가 정상으로 판정되고 마지막 성공 시각이 함께 제공된다

#### Scenario: 차단 상태
- **WHEN** 미실행에 해당하지 않는 상태에서 마지막으로 완료된 회차가 차단이면(그 뒤에 건너뜀 회차만 있어도)
- **THEN** 상태가 차단으로 판정된다

#### Scenario: 워커가 멈춘 상태
- **WHEN** 기대 주기의 여러 배에 해당하는 시간 동안 어떤 기록도 남지 않았으면
- **THEN** 상태가 미실행으로 판정된다

#### Scenario: 기록이 전혀 없을 때
- **WHEN** 회차 기록이 하나도 없으면
- **THEN** 오류 없이 미실행 상태로 판정된다
