## ADDED Requirements

### Requirement: WAF 차단 리다이렉트 감지
어댑터는 소스가 HTTP 상태 200의 HTML 본문으로 알리는 차단뿐 아니라, **WAF 차단 페이지로의 리다이렉트**로 알리는 차단도 차단으로 감지해야 한다(MUST). 법원경매정보의 경우 3xx 응답의 `Location` 경로가 `/error.html`이면 WAF 차단이다(2026-10-18 관측: `302 Found`, `Location: /error.html`, 본문 "contrary to the Web firewall security policies have been blocked").

이 감지는 세션 초기화·목록 검색·사진 상세 조회 등 어댑터가 소스에 보내는 모든 요청에 적용되어야 하며(SHALL), 감지된 차단은 본문 기반 WAF 차단과 같은 차단 오류로 알려야 한다(SHALL) — 그래야 수집기·사진 워커의 기존 차단 처리(차단 기록, 공유 백오프, 로테이션 위치 유지, 같은 회차의 다음 법원 미요청)가 그대로 적용된다. 어댑터는 리다이렉트를 따라가서는 안 된다(MUST NOT).

차단 페이지가 아닌 곳으로의 리다이렉트와 그 밖의 비정상 상태(4xx·5xx)는 차단이 아니라 일반 요청 실패로 알려야 한다(SHALL). 차단 페이지 경로 같은 소스 고유 판정 규칙은 어댑터 밖으로 새어 나가서는 안 된다(MUST NOT).

#### Scenario: 세션 초기화에서 WAF 리다이렉트
- **WHEN** 수집 회차의 세션 초기화 요청이 `302`와 `Location: /error.html`을 받으면
- **THEN** 그 회차는 일반 실패가 아닌 차단으로 기록되고, 공유 백오프가 기록되며, 로테이션 위치는 그 법원에 머문다

#### Scenario: 목록 검색 중 WAF 리다이렉트
- **WHEN** 목록 검색 요청(첫 페이지 또는 이후 페이지)이 WAF 차단 페이지로 리다이렉트되면
- **THEN** 그 회차는 차단으로 중단되고 같은 회차에서 다음 페이지·다음 법원으로 요청을 보내지 않는다

#### Scenario: 사진 조회 중 WAF 리다이렉트
- **WHEN** 사진 워커의 세션 초기화 또는 사진 상세 요청이 WAF 차단 페이지로 리다이렉트되면
- **THEN** 그 물건은 실패로 기록되지 않고, 공유 백오프가 기록되며, 남은 물건을 요청하지 않고 회차가 차단으로 기록된다

#### Scenario: 차단 페이지가 아닌 리다이렉트
- **WHEN** 소스가 `/error.html`이 아닌 곳으로 3xx 리다이렉트를 응답하면
- **THEN** 일반 요청 실패로 기록되고 백오프는 걸리지 않는다

#### Scenario: Location 헤더 없는 리다이렉트
- **WHEN** 소스가 `Location` 헤더 없이 3xx를 응답하면
- **THEN** 일반 요청 실패로 기록된다
