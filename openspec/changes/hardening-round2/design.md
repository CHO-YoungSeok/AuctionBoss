# Design: hardening-round2

## Context

동기는 proposal.md 참조. 10회차와 같이 발견 주도적이지만 초점이 다르다:

- 10회차: **아직 안 밟은 경로**를 밟는다(정적·단발 검증)
- 11회차: **시간이 지나야 드러나는 것**을 본다(연속 운용)

지금까지 검증되지 않은 채 남은 것:

| 항목 | 왜 아직 미검증인가 |
|---|---|
| 연속 운용 | 모든 검증이 1회차 또는 수동 실행이었다 |
| 재분석 경로 | 후보가 없어 `maxReanalysisPerRun`·쿨다운이 한 번도 동작한 적 없다 |
| 백오프 복귀 | 차단이 안 나서 실제 복귀를 본 적 없다 |
| 보관 상한 | 상한을 인위적으로 낮춰서만 확인했다 |
| 초기 적재 경험 | 389건 중 28건만 분석된 상태를 사용자 눈으로 본 적 없다 |

## Goals / Non-Goals

**Goals:**
- 시간·반복에서만 드러나는 문제 찾기
- 재분석 경로를 실데이터로 처음 실증
- 최종 상태를 정직하게 기록 — 무엇이 검증됐고 무엇이 안 됐는지

**Non-Goals:**
- 새 기능, 보고서 품질 개선, 전국 확대

## Decisions

### D1. 연속 운용은 실측 안전 범위 안에서, 관측하며

전체 수집이 회차당 13요청 / 57초이고 차단 임계는 5분에 15회 미만이다. 10분 주기는 1회차 기준으로 안전이 확인됐다.

- **주기를 줄이지 않는다.** 관측 시간을 벌겠다고 주기를 3분으로 낮추면 밀도가 3배가 되어 실측 근거를 벗어난다. 관측이 오래 걸리는 것은 받아들인다.
- 다만 **수집 범위를 줄여 회차를 가볍게 하는 것은 허용**한다(예: 기일 범위를 며칠로). 요청 밀도를 낮추면서 회차 반복은 그대로 볼 수 있다. 조정했으면 값과 이유를 기록한다.
- **차단이 나면 즉시 중단하고 기록한다.** 그건 실패가 아니라 "연속 운용의 한계"라는 답이다.

### D2. 재분석은 인위적으로 유발한다

자연 발생을 기다리면 유찰이 실제로 일어나야 하는데 그건 몇 주 단위다.

- 이미 분석된 물건의 감시 필드를 직접 바꿔 후보를 만든다. 이건 **소스를 속이는 것이 아니라 수집 결과를 조작하는 것**이라, 재분석 로직 자체의 검증에는 유효하다.
- **쿨다운 검증이 특히 중요하다.** 지금까지 한 번도 동작한 적 없고, 이 값(24시간)이 비용 폭주를 막는 유일한 장치다. 방금 분석된 물건이 또 바뀌었을 때 재분석되지 않는 것을 봐야 한다.
- 쿨다운을 검증하려면 24시간을 기다릴 수 없으므로, **설정을 짧게 조정해 동작을 확인**하고 원복한다. 조정값과 원복을 기록한다.

### D3. 초기 적재는 판단만 하고 구현은 신중히

389건 × 회차당 5건 = 78회차 = 13시간이다.

- 이건 **의도된 비용 통제**의 결과이지 결함이 아니다. 다만 사용자 경험 관점에서 받아들일 만한지는 별개 문제다.
- 7회차가 "분석 없이도 판단 가능하게" 만든 것이 정확히 이 상황을 위한 것이었다. **그게 실제로 작동하는지 실데이터로 확인**하는 것이 먼저다. 작동한다면 13시간은 문제가 아니다.
- 조정이 필요하다고 판단되면 제안하되, **이번 사이클에서 구현할지는 범위와 위험을 보고 정한다.** 마지막 사이클에 새 기능을 넣는 것은 위험하다.

### D4. 최종 정리는 "검증된 것과 아닌 것"을 분리한다

이 프로젝트에서 반복적으로 값졌던 것은 **모르는 것을 안다고 하지 않는 것**이었다. 마지막 문서도 같은 원칙을 따른다.

- 검증된 것: 무엇을 어떻게 확인했는지 근거와 함께
- 검증되지 않은 것: **무엇이 있어야 검증할 수 있는지**까지. "미검증"만 남기면 다음 사람이 같은 고민을 반복한다
- 실서비스로 쓰려면 무엇이 더 필요한지 — 인증, 다일 연속 운용, 권리분석 데이터 소스 등

## Risks / Trade-offs

- [연속 운용 중 차단] → 실측 범위를 지키고 차단 시 즉시 중단. 차단도 결과로 기록한다.
- [관측에 시간이 오래 걸림] → 주기를 낮추지 않고 수집 범위를 줄여 대응한다. 시간은 받아들인다.
- [쿨다운 검증을 위한 설정 조정을 원복하지 않음] → 조정과 원복을 태스크로 명시하고 최종 게이트에서 설정 파일을 확인한다.
- [마지막 사이클에 새 기능을 넣어 회귀] → 초기 적재 조정은 판단까지만 하고 구현은 위험을 보고 결정한다.

## Open Questions

- 며칠 단위 연속 운용은 이 사이클에서도 검증할 수 없다. 몇 시간 관측으로 무엇을 말할 수 있고 무엇을 말할 수 없는지 결과에 명시한다.
