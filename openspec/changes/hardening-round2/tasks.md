## 2. 연속 운용 관측 (아직 아무도 하지 않은 것)

지금까지 모든 검증은 한 회차 또는 수동 실행이었다. **회차가 자동으로 반복될 때만 드러나는 것**을 본다.

- [ ] 2.1 서버·수집기·분석기를 함께 띄우고 **여러 회차가 자동으로 도는 것을 관측**. 수집 주기는 실측 안전 범위(회차당 13요청/57초)를 지키되, 관측 시간을 확보하기 위해 조정해도 된다. **조정했다면 그 값과 이유를 기록**할 것
- [ ] 2.2 관측할 것: 중첩 방지가 실제로 동작하는가, 회차 기록이 누적되는가, `/status`가 시간에 따라 상태를 바꾸는가, 보관 상한이 실제로 걸리는가
- [ ] 2.3 **차단이 발생하면 즉시 중단하고 조건을 기록**할 것. 재시도 루프 금지. 차단은 연속 운용의 한계를 알려주는 결과다
- [ ] 2.4 분석 큐가 회차를 거듭하며 줄어드는 것을 관측. 회차당 5건 한도가 실제로 지켜지는가
- [ ] 2.5 관측 종료 후 모든 프로세스를 정리하고, 사용한 Claude 호출 수와 실제 사이트 요청 수를 기록할 것

## 3. 재분석 경로 실증 (한 번도 동작한 적 없음)

`maxReanalysisPerRun`과 쿨다운은 재분석 후보가 없어서 실데이터로 동작한 적이 없다.

- [ ] 3.1 이미 분석된 물건의 감시 필드를 실제로 바꿔 재분석 후보를 만들 것
- [ ] 3.2 분석 워커가 그 물건을 재분석하고 **이전 분석이 보존되는 것**을 확인
- [ ] 3.3 **쿨다운이 실제로 동작하는 것**을 확인 — 방금 분석된 물건이 또 바뀌어도 쿨다운 안에서는 재분석되지 않아야 한다
- [ ] 3.4 신규 분석이 재분석보다 우선하는 것을 실데이터로 확인(미분석 물건이 남아 있는 상태에서)
- [ ] 3.5 재분석된 보고서를 읽고 새 값이 실제로 반영됐는지 확인
