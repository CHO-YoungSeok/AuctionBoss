## 1. 표시 헬퍼

- [x] 1.1 저감률(최저가 ÷ 감정가) 계산·포맷과 **단계 구분** 판정을 순수 함수로 작성. 감정가 0·null, 최저가 null, 비율이 1을 넘는 경우를 전부 가드하고 `NaN`/`Infinity`가 화면에 새지 않는 것을 테스트
- [x] 1.2 단계 구분은 **색에만 의존하지 않고 텍스트 라벨을 함께** 반환할 것. 라벨이 `Record`로 정의돼 단계를 추가하면 컴파일이 깨지게 할 것
- [x] 1.3 지역 요약 함수: 구조화 소재지(sido/sigungu/dong)가 있으면 지역을 앞세운 짧은 표기를, 없으면 기존 `address`를 반환. 부분적으로만 있는 경우(시도만 있고 동이 없는 등)도 테스트
- [x] 1.4 면적당 가격은 `src/lib/domain/price.ts`의 `computePricePerArea`를 **재사용**할 것. 목록용으로 다시 구현하지 말 것

## 2. 목록 화면

- [x] 2.1 목록에 저감률과 면적당 가격 열을 추가. 계산 불가한 물건은 "-"로 표시되고 행 전체는 정상 렌더링되는 것을 확인
- [x] 2.2 저감률에 단계 구분을 적용하고, 색 없이 텍스트만으로도 구별되는 것을 확인
- [x] 2.3 소재지를 지역 요약으로 교체. 구조화 값이 있는 물건과 없는 물건(이 기능 이전 수집분)이 섞인 데이터로 둘 다 정상 표시되는 것을 확인
- [x] 2.4 **회귀**: 기존 필터·정렬·페이지네이션·관심 토글이 전부 그대로 동작하고 `total`이 변하지 않는 것을 확인. 목록 쿼리의 `WHERE`/`ORDER BY`를 건드리지 말 것

## 3. 분석 상태 표시

- [x] 3.1 분석 최신성 판정(대기 중 / 최신 / 갱신 예정)을 구현. **재분석 대상 선정과 같은 규칙을 재사용**할 것 — 화면용 판정을 새로 만들면 워커와 다른 답이 나온다
- [x] 3.2 세 상태를 상세 화면에 배지로 표시. "갱신 예정"은 표시 중인 분석이 현재 값 기준이 아닐 수 있다는 경고로 읽히게 문구를 쓸 것
- [x] 3.3 세 상태 각각을 테스트로 고정: 분석 없음 / 분석 후 변경 없고 버전 같음 / 분석 후 감시 필드 변경됨 / 분석 후 프롬프트 버전이 다름
- [x] 3.4 대기 순번이나 예상 시각은 만들지 말 것 — 재분석·쿨다운·한도가 얽혀 정확한 예측이 불가능하고 틀린 예측은 없느니만 못하다

## 4. 원본 확인 경로

- [x] 4.1 상세에 "법원경매정보에서 확인" 블록 추가: 홈 링크(`https://www.courtauction.go.kr/pgj/index.on`) + 법원명·사건번호를 `<input readonly>`로 제공 + 그 값으로 검색하라는 한 줄 안내
- [x] 4.2 **딥링크를 만들지 말 것.** 물건별 GET URL이 존재하지 않는다는 것이 조사로 확인됐다(design Context). `w2xPath`로 상세 화면을 강제로 여는 링크도 만들지 말 것 — 데이터 없이 열려 빈 화면이나 오류가 된다
- [x] 4.3 실제 서버에서 블록이 렌더되고 법원명·사건번호 값이 정확한 것을 확인

## 5. 상세 재배치

- [x] 5.1 상세를 판단 순서로 재배치: 가격(감정가·최저가·저감률·면적당 가격·차수별 추이) → 물건 개요(용도·면적·소재지·매각기일) → AI 분석 → 변경 이력 → 원본 확인 → 부가 정보

- [x] 5.3 확장 필드가 비어 있는 물건(이 기능 이전 수집분)도 오류 없이 렌더되는 것을 확인
