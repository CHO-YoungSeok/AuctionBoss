# web-data-port Specification

## Purpose
웹 화면과 화면용 라우트가 데이터베이스를 직접 열지 않고 데이터 포트 하나를 거쳐 데이터를 읽고 쓰게 한다. 포트 뒤의 데이터 원천은 Spring 백엔드 하나다(SQLite 구현체는 5단계 `migrate-data-and-cutover`에서 은퇴). 포트는 응답을 검증하고 실패를 부분 렌더 없이 드러내며, 화면이 보내는 요청 형식이 백엔드 계약 골든과 어긋나지 않게 한다.

## Requirements

### Requirement: 데이터 원천 선택
데이터 포트의 원천은 Spring 백엔드(`spring`) 하나여야 한다(SHALL). 원천 환경 변수를 설정하지 않으면 Spring 백엔드여야 하며(SHALL), 백엔드 주소는 환경 변수로 받아야 한다(SHALL).

은퇴한 기존 데이터베이스 값(`sqlite`)은 은퇴했음을 알리는 오류로, 알 수 없는 값과 주소 없는 설정은 원인을 밝힌 오류로 화면을 그리기 전에 실패해야 하며(SHALL), 다른 원천으로 조용히 바꿔 동작하거나 데이터베이스 파일을 만들면 안 된다(MUST NOT).

#### Scenario: 기본 원천
- **WHEN** 데이터 원천 환경 변수 없이 백엔드 주소만 설정해 웹 앱을 띄우고 화면을 연다
- **THEN** 화면은 백엔드 API에서 읽은 데이터를 보여준다

#### Scenario: 은퇴한 원천 값
- **WHEN** 데이터 원천을 `sqlite`로 설정하고 화면을 연다
- **THEN** 기존 데이터베이스 원천이 은퇴했다는 오류로 실패하고, 데이터베이스 파일을 열거나 만들지 않는다

#### Scenario: Spring 원천
- **WHEN** 데이터 원천을 `spring`으로, 백엔드 주소를 개발용 백엔드로 설정하고 화면을 연다
- **THEN** 화면은 백엔드 API에서 읽은 데이터를 보여주고, 데이터베이스 파일을 열거나 만들지 않는다

#### Scenario: 잘못된 원천 값
- **WHEN** 데이터 원천을 알 수 없는 값으로 설정하고 화면을 연다
- **THEN** 허용 값(`spring`)을 알려 주는 오류로 실패한다

#### Scenario: 주소 없음
- **WHEN** 백엔드 주소 없이 웹 앱을 띄우고 화면을 연다
- **THEN** 백엔드 주소 환경 변수가 필요하다는 오류로 실패한다

### Requirement: 백엔드 응답 검증과 실패 처리
Spring 원천은 웹 서버에서만 백엔드를 호출해야 하며(SHALL), 브라우저가 백엔드에 직접 요청하게 만들면 안 된다(MUST NOT). 모든 응답 본문은 기대 형식으로 검증한 뒤에 화면에 넘겨야 한다(SHALL).

백엔드에 연결할 수 없거나, 정해진 시간 안에 응답이 없거나, 기대하지 않은 상태 코드가 오거나, 본문이 기대 형식과 다르면 그 화면 요청은 오류로 끝나야 한다(SHALL). 일부 데이터만으로 화면을 그리거나 다른 원천으로 대신 읽으면 안 된다(MUST NOT). 없는 물건(404)은 오류가 아니라 기존과 같은 "찾을 수 없음" 화면이어야 한다(SHALL). 오류 기록에는 요청 경로와 원인을 남기되 비밀 값은 남기면 안 된다(MUST NOT).

#### Scenario: 형식이 다른 응답
- **WHEN** 백엔드가 물건 목록 응답에서 필수 필드를 빼고 돌려준다
- **THEN** 목록 화면 요청은 오류로 끝나고, 빠진 필드와 요청 경로가 서버 로그에 남는다

#### Scenario: 백엔드 중단
- **WHEN** Spring 원천으로 설정된 웹 앱에서 백엔드를 멈춘 뒤 화면을 연다
- **THEN** 화면 요청은 오류로 끝나고, 기존 데이터베이스의 데이터가 대신 보이지 않는다

#### Scenario: 없는 물건 상세
- **WHEN** Spring 원천으로 존재하지 않는 물건의 상세 화면을 연다
- **THEN** 기존 데이터베이스 원천과 같은 "찾을 수 없음" 화면이 나온다

### Requirement: 화면당 백엔드 요청 수 상한
Spring 원천은 화면 하나를 그릴 때 보내는 백엔드 요청 수가 데이터 행 수와 무관하게 정해진 상한 이하여야 한다(SHALL). 상한은 다음과 같다.

| 화면·라우트 | 상한 |
| --- | --- |
| 물건 목록 | 6 |
| 물건 상세 | 5 |
| 관심 물건 | 2 |
| 변동 피드 | 2 |
| 워커 상태 | 11 |
| 관심 토글 폼, 읽음 처리 폼, 사진 파일 | 각 1 |

물건이나 회차 하나마다 요청을 보내는 방식(N+1)은 허용하지 않는다(MUST NOT).

#### Scenario: 행 수와 무관한 요청 수
- **WHEN** 관심 물건 4건과 30건인 상태에서 각각 관심 물건 화면을 그린다
- **THEN** 두 경우 모두 백엔드 요청 수가 2 이하로 같다

#### Scenario: 상세 화면 요청 수
- **WHEN** 분석 이력·변경 이력·사진이 모두 있는 물건의 상세 화면을 그린다
- **THEN** 백엔드 요청 수가 5 이하다

### Requirement: 화면용 폼 엔드포인트
관심 토글 폼(`POST /api/bookmarks/toggle`)과 읽음 처리 폼(`POST /api/feed/mark-read`)은 웹 앱이 계속 받아야 하며(SHALL), 실제 등록·해제·읽음 처리는 데이터 포트로 해야 한다(SHALL). 처리에 성공하면 303으로 `returnTo`에 돌아가야 하고(SHALL), `returnTo`는 지금과 같은 규칙(같은 오리진의 `/`로 시작하는 경로, `//`로 시작하면 거절)으로 검증해 통과하지 못하면 물건 목록으로 돌아가야 한다(SHALL). 없는 물건의 토글은 404여야 한다(SHALL). 읽음 처리는 이 폼을 제출했을 때만 일어나야 한다(SHALL).

#### Scenario: 토글 후 복귀
- **WHEN** 목록 화면의 관심 토글 폼을 `returnTo=/?sort=minBidPrice&page=2`로 제출한다
- **THEN** 303으로 같은 경로에 돌아가고, 백엔드의 관심 목록에 그 물건이 담겨 있다

#### Scenario: 외부 주소 복귀 거절
- **WHEN** `returnTo=//evil.example`로 폼을 제출한다
- **THEN** 303으로 물건 목록(`/`)에 돌아간다

#### Scenario: 없는 물건 토글
- **WHEN** 존재하지 않는 물건 id로 토글 폼을 제출한다
- **THEN** 404이고 관심 목록이 바뀌지 않는다

### Requirement: 화면용 사진 파일 경로
화면의 사진은 지금처럼 웹 앱의 `GET /api/photos/{itemId}/{seq}`로 내려가야 하며(SHALL), 웹 앱은 데이터 포트로 사진을 읽어야 한다(SHALL). 웹 앱은 백엔드 사진 API의 상태 코드, 본문 바이트, 콘텐츠 형식, 캐시 헤더를 그대로 전달해야 한다(SHALL).

#### Scenario: 사진 전달
- **WHEN** 사진이 저장된 물건의 사진 경로를 요청한다
- **THEN** 백엔드가 준 것과 같은 바이트, 콘텐츠 형식, 캐시 헤더로 응답한다

#### Scenario: 사진 없음
- **WHEN** 기록이 없는 순번의 사진을 요청한다
- **THEN** 백엔드와 같은 404와 본문 문자열을 돌려준다

### Requirement: 웹 앱과 분석 워커의 데이터 접근 경계
웹 화면(물건 목록, 물건 상세, 관심 물건, 변동 피드, 워커 상태)과 웹 앱에 남는 라우트(헬스체크, 관심 토글 폼, 읽음 처리 폼, 사진 파일)는 데이터 포트를 통해서만 데이터를 읽고 써야 한다(SHALL). 웹 앱과 분석 워커의 코드는 데이터베이스 드라이버를 가져오면 안 된다(MUST NOT). 분석 워커는 웹 앱 모듈과 데이터 포트를 가져오면 안 된다(MUST NOT) — 분석 워커는 서버 API로만 통신한다.

이 경계는 정적 검사(린트)로 강제해야 하며(SHALL), 예외는 두지 않는다. 테스트 코드도 데이터베이스 드라이버를 가져오면 안 된다(MUST NOT).

#### Scenario: 화면 코드의 직접 접근 금지
- **WHEN** 화면 페이지나 웹 앱 라우트에 데이터베이스 드라이버를 가져오는 코드를 넣고 린트를 실행한다
- **THEN** 린트가 실패하고 해당 파일과 금지된 가져오기가 보고된다

#### Scenario: 분석 워커의 웹 앱 모듈 사용 금지
- **WHEN** 분석 워커 코드에 데이터 포트나 웹 앱 모듈을 가져오는 코드를 넣고 린트를 실행한다
- **THEN** 린트가 실패한다
